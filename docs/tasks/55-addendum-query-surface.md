# 55 — Authoring and query surface: the new kinds through `new`, `list`, `show`, `gaps`, `trace`

## Depends on

## Goal

Resources and behaviors become first-class citizens of the commands that
already exist: authorable with `ab new`, visible in `ab list` / `ab show` /
`ab gaps` / `ab trace` — with `--json` everywhere, per the addendum's §0 rule
that a thing unreachable from the CLI is wrong. Plus the owner-inheritance
piece of §7, which lives in the query layer because that is where grouping
by owner happens.

> overridden. One level of inheritance, no deeper.

## What to build

- `absicht.cli._common.Kind`: add `RESOURCE = "resource"` and
  `BEHAVIOR = "behavior"`. **Not** `note` — see
  `50-addendum-conventions.md`.
- `ab new resource SLUG` / `ab new behavior SLUG`: templates in
  `absicht.new` matching the existing kinds' style. The resource template
  carries `resource_kind` and `technology` placeholders; the behavior
  template carries `trigger` and a commented example observation showing
  the `#obs-1` anchoring, `outcome`, `timing` — the template is where an
  author first meets the format, make the example the worked one from
  addendum §3.3. Observation ids are authored inline, never generated by
  `ab new` (same boundary as criteria — see `00-conventions.md` Identity).
- `ab list resource` / `ab list behavior`: whatever the generic path needs.
  `ab list behavior` additionally supports `--lifecycle {active,superseded}`
  and shows the *derived* scope column once
  [56](56-derived-scope-composition.md) lands — coordinate: if 56 is not
  merged yet, leave the column out rather than deriving it here.
- `ab show behavior:x`: observations render in the body (statement, at,
  outcome, effective timing); refs in/out already come from `Index`.
- `ab gaps`: behaviors and resources join the worklist by their `state`
  like every element; additionally a behavior with zero observations is a
  gap line (the policy rule's query-side twin, the way unowned elements
  appear both places).
- Owner inheritance (§7): where `gaps`/`list --owner` group unknowns, an
  element in state `unknown` with no `owner` reports the owner of the
  element that *references* it when exactly one referencing element has
  one — one level, no deeper, never stored. Surface it distinguishably
  (e.g. `owner: platform (inherited)` in text, a separate
  `owner_inherited` field in `--json` — additive, per the envelope rules).
- `ab trace`: `realizes`, `supersedes` and observation `at` edges
  participate in path walks (they should already, via `iter_references` —
  assert, and fix if the trace graph filters kinds).

- `ab new` for both kinds produces files that `ab check` accepts and that
  land in the right directories; `--print` variant byte-stable.
- `ab list behavior --lifecycle superseded` filters; `--json` envelopes.
- `ab show` on the clean fixture's composing behavior names the composed
  behavior among refs out.
- Owner inheritance: inherited owner appears and is marked; an element with
  its own owner is never overridden; two referencing owners → no inheritance
  (ambiguity is not a guess); depth stops at one level.
